#+title: Bits Operations Guide
#+author: James Conroy-Finn

* Overview

Bits runs on =compute= as rootless Podman containers managed by systemd
(Quadlet). The =bits= user owns the containers; CI deploys as =ci= through sudo.

* Quick Reference

All commands run on =compute=. SSH there first:

#+begin_src sh
ssh compute
#+end_src

** Service Status

=bits-proxy= holds port 3000 and forwards it to the live colour, =blue= or
=green=.

#+begin_src sh
sudo -u bits XDG_RUNTIME_DIR=/run/user/$(id -u bits) systemctl --user status bits-proxy.service bits-blue.service bits-green.service

# Which colour is live
sudo -u bits XDG_RUNTIME_DIR=/run/user/$(id -u bits) systemctl --user cat bits-proxy.service | grep ExecStart

# Health through the public port
curl -s http://127.0.0.1:3000/healthz
#+end_src

** View Logs

#+begin_src sh
# Recent app logs, whichever colour wrote them
sudo journalctl -n 100 CONTAINER_NAME=bits-blue CONTAINER_NAME=bits-green

# Follow app logs
sudo journalctl -f CONTAINER_NAME=bits-blue CONTAINER_NAME=bits-green

# Transactor logs
sudo journalctl -n 100 CONTAINER_NAME=bits-transactor

# Postgres logs
sudo journalctl -n 100 CONTAINER_NAME=bits-postgres
#+end_src

** Restart Services

Restarting the live colour drops traffic until it starts again; a deploy swaps
colours without that.

#+begin_src sh
# Restart the live colour (blue here)
sudo -u bits XDG_RUNTIME_DIR=/run/user/$(id -u bits) systemctl --user restart bits-blue.service

# Restart transactor
sudo -u bits XDG_RUNTIME_DIR=/run/user/$(id -u bits) systemctl --user restart bits-transactor.service
#+end_src

** Roll Back

The registry keeps only the newest deploy's tags. To roll back, revert the
change and push; CI builds and deploys it like any other commit.

The registry refuses anonymous pulls. The =bits= user stays signed in from CI
deploys; if a pull fails with =unauthorized=, the next deploy logs it in again.

** Shell Alias

Add to =~/.zshrc= on compute for convenience:

#+begin_src sh
alias pci='sudo -u bits XDG_RUNTIME_DIR=/run/user/$(id -u bits) podman'
alias sci='sudo -u bits XDG_RUNTIME_DIR=/run/user/$(id -u bits) systemctl --user'
#+end_src

Then:

#+begin_src sh
sci status bits-proxy.service
sci restart bits-transactor.service
pci images
pci logs bits-blue
#+end_src

* Services

| Service         | Port  | Description              |
|-----------------+-------+--------------------------|
| bits-proxy      | 3000  | Public port, live colour |
| bits-blue       | 3001  | Application server       |
| bits-green      | 3002  | Application server       |
| bits-transactor | 4334  | Datomic transactor       |
| bits-postgres   | 5432  | PostgreSQL (internal)    |
| bits-jaeger     | 16686 | Jaeger UI (localhost)    |

* Startup Order

Systemd manages dependencies:

1. =bits-postgres.service= starts first
2. =bits-transactor.service= waits for postgres
3. =bits-proxy.service= wants the live colour, so a boot starts whichever colour
   last served; that colour waits for the transactor
4. =bits-jaeger.service= starts independently (optional)

* Health

=/healthz= asks every component whether it can reach its dependencies: Datomic
once the transactor confirms a sync, Postgres once the pool hands out a valid
connection. =/livez= asks only whether each component's own state is intact.
Both answer 200 or 503 with one line per component, and give up on a check
after two seconds. Neither needs a session or a known host.

* Deployment

CI deploys every push to =main= that passes its tests, blue/green:

1. Builds the image and pushes it as =<date>-<sha>= and =latest=
2. =deploy.sh= renders the idle colour's quadlet with the new image, pulls it,
   and installs the quadlet files; the live colour's file is left alone
3. Restarts postgres, the transactor or jaeger only if their definitions changed
4. Starts the idle colour and waits for its =/healthz=; if it never answers 200,
   the deploy stops it and fails, and traffic stays where it was
5. Points =bits-proxy= at the new colour and restarts it. The socket stays open,
   so new connections wait rather than fail; connections already open through
   the old proxy close
6. Stops the old colour, prunes unused images, and deletes registry tags older
   than the newest deploy

The transactor is pinned separately, in =deploy/bits-transactor.container=, to a
dated build of =invetica/datomic-transactor=. Change it on purpose; the
=1.0.7187= and =latest= tags move with every Datomic build.

* Secrets

Secrets are managed by ragenix in =~/.config/setup=:

| File                              | Contents                    |
|-----------------------------------+-----------------------------|
| bits-environment-file             | App env vars (DATABASE_URL) |
| bits-postgres-environment-file    | Postgres credentials        |
| bits-transactor-environment-file  | Transactor SQL_URL          |

To update secrets:

#+begin_src sh
cd ~/.config/setup
echo "NEW_VAR=value" | just encrypt secrets/bits-environment-file.age
git add secrets/ && git commit -m "Update bits secret"
git push
ssh compute "sudo nixos-rebuild switch --flake ~/.config/setup"
#+end_src

* Troubleshooting

** 502 Bad Gateway

Cloudflare can reach the tunnel but nothing answers on port 3000.

1. Check the proxy and colours: =sci status bits-proxy.service bits-blue.service bits-green.service=
2. Check health: =curl -s http://127.0.0.1:3000/healthz=
3. Check logs: =sudo journalctl -n 50 CONTAINER_NAME=bits-blue CONTAINER_NAME=bits-green=

** Container Won't Start

Check for image pull issues:

#+begin_src sh
pci pull code.invetica.team/jcf/bits:latest
#+end_src

Check quadlet generation:

#+begin_src sh
sudo -u bits XDG_RUNTIME_DIR=/run/user/$(id -u bits) \
  /nix/store/*-podman-*/bin/podman system connection list
#+end_src

** Database Connection Errors

Verify postgres is healthy:

#+begin_src sh
sci status bits-postgres.service
pci exec bits-postgres pg_isready -U bits -d bits
#+end_src

** Transactor Errors

Check transactor logs for storage/connection issues:

#+begin_src sh
sudo journalctl -n 100 CONTAINER_NAME=bits-transactor
#+end_src

* Observability

** Jaeger (Tracing)

Access via SSH tunnel:

#+begin_src sh
ssh -L 16686:localhost:16686 compute
#+end_src

Then open http://localhost:16686

** Logs

All container logs go to journald. Query by container name:

#+begin_src sh
sudo journalctl CONTAINER_NAME=bits-blue CONTAINER_NAME=bits-green --since "1 hour ago"
#+end_src
